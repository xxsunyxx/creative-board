# 推理引擎（设计稿 v0.1）

> 目标：把「开始推理」做成一个可解释、可撤销、可计费的图推理流水线。

## 1. 目标

输入一张画布图，输出一组节点内容补丁：

- 空便签：推断角色 + 生成内容。
- 空灵感：补一个能推进下游的灵感 / 前提 / 素材。
- 空过程：补中间机制 / 因果链 / 转化过程。
- 空结果：综合入线节点，收敛出结论。
- 后续任务：候选问题、结果预览、文档。

要求：

- 角色感知：灵感 / 过程 / 结果用不同提示词。
- 图感知：只看相关邻居，不把整张画布塞给模型。
- 可撤销：一次运行产生的修改可以整体回滚。
- 可计费：记录 token / 费用，「本次」和「本画布合计」。
- 可失败：模型错误不污染画布，失败节点保持空白。

## 2. 任务类型

```ts
type InferenceTask =
  | { type: "fill_blank_notes"; canvasId: string; hint?: string }
  | { type: "generate_questions"; nodeId: string }
  | { type: "generate_result"; nodeId: string; question: string }
  | { type: "suggest_missing_nodes"; canvasId: string };
```

首版只做 `fill_blank_notes`，其余为 M5b / M6 预留。

## 3. 核心流程

```
开始推理
  ↓
1. 图快照：节点 / 边 / 维度框 / 权重 / 颜色 / 备注
  ↓
2. 找空便签 + 本地角色推断
  ↓
3. 拓扑排序，拆成推理波次
  ↓
4. 逐节点组装上下文（1 跳邻居 + 维度路径）
  ↓
5. 调用 provider，拿结构化 JSON
  ↓
6. 校验 / 修复 / 生成补丁
  ↓
7. 应用补丁 + 记录 run / patch / usage
  ↓
8. 返回结果，UI 显示本次消耗，可撤销
```

## 4. 图快照与角色推断

快照内容：

- 节点：id、role、roleLocked、title、content、weight、color、位置。
- 边：from、to、方向。
- 维度框：关系类型、已选主维度 / 细节路径。
- 画布：名称、描述（作为默认目标）。

本地角色推断：

- 无入有出 → inspiration
- 有入有出 → process
- 有入无出 → result
- 孤立 → blank / inspiration（插入时定）
- `roleLocked = true` 时保持原角色。

AI 只负责内容；角色默认由拓扑决定，模型可以在 JSON 里建议覆盖，但需要高置信度。

## 5. 推理波次

不能一次把所有空便签都生成，因为下游需要上游内容。

- 把空便签按入线依赖做拓扑排序。
- 每轮只生成「上游已就绪」的节点：
  - 第 1 波：没有入线的空灵感。
  - 第 2 波：入线已就绪的过程 / 结果。
  - 继续，直到所有空便签处理完。
- 有环时：把环里的节点作为一批，使用现有内容 + 标题作为上下文，不阻塞其他节点。

首版并发度 2-3，逐节点调用；后续再合并成批量。

## 6. 上下文组装

每个节点只带 1 跳邻居，避免上下文爆炸：

```json
{
  "canvas": { "name": "...", "description": "..." },
  "hint": "用户本次推理提示（可空）",
  "node": {
    "id": "...",
    "role": "process",
    "title": "过程",
    "content": "",
    "weight": 5,
    "colorLabel": "组织创新"
  },
  "incoming": [
    {
      "id": "...",
      "role": "inspiration",
      "title": "...",
      "content": "...",
      "weight": 8,
      "edge": {
        "relationTypes": ["因果"],
        "selectedPaths": ["机制 / 触发器"]
      }
    }
  ],
  "outgoing": [ ... ]
}
```

规则：

- 邻居正文截断到 600-800 字。
- 高 weight 优先保留；低 weight 可截断。
- 维度框只带「关系类型 + 已选路径」，不带完整树。
- 总输入控制在 6k-8k tokens；超出时先截断低权重邻居。
- 不把 API key、内部 id、数据库字段发给模型（id 可保留，用于回填）。

## 7. 角色提示词

### 灵感

> 你是灵感补全器。根据出线邻居和关系，补一个能推进它们的灵感、前提、素材或问题。只输出这个灵感本身，不要解释。

### 过程

> 你是过程推理器。根据入线和出线，补一个中间机制 / 因果链 / 转化过程。优先使用入线维度框里的关系类型和已选维度。输出一段可继续追问的过程描述。

### 结果

> 你是结果收敛器。综合入线节点，输出一个结论 + 2-3 条支撑理由。不要引入上下文里没有的新事实。如果证据不足，明确标注「假设」。

### 空白

> 先根据入线 / 出线判断这个节点更像灵感、过程还是结果，再生成内容。

## 8. 结构化输出

```json
{
  "nodeId": "...",
  "role": "inspiration | process | result",
  "title": "可选短标题",
  "content": "生成内容",
  "confidence": 0.0,
  "rationale": "可选，调试用"
}
```

校验：

- `nodeId` 必须属于本次请求。
- `role` 必须是合法角色。
- `content` 长度 10-1200 字；去掉前后空白。
- 非法 JSON：带错误信息重试 1 次；仍失败则标记该节点失败。
- 不自动创建新节点、不改边、不改维度。

## 9. Provider 适配

统一接口：

```ts
interface AiProviderClient {
  generateJson<T>(input: {
    apiKey: string;
    model: string;
    system: string;
    user: string;
    schema: unknown;
    signal?: AbortSignal;
  }): Promise<{ data: T; usage: Usage; raw?: string }>;
}
```

适配：

- **OpenAI**：结构化输出 / JSON schema。
- **Anthropic**：Messages + tool use，工具参数即 JSON schema。
- **DeepSeek**：OpenAI 兼容 chat completions + JSON mode；schema 放提示词，服务端校验。
- **Mock**：当前模板，用于无 key / 测试。

Key 处理：

- 客户端从 localStorage 读出，随请求发到本地 API。
- 服务端只用于本次调用，不写日志、不落盘。
- 请求结束即丢弃。

## 10. 应用与撤销

- 推理返回补丁，前端**立即应用**，并在顶部显示「本次推理完成 · 撤销」。
- 同时写入：
  - `inference_runs`：id、canvasId、status、task、provider、model、startedAt、finishedAt、error。
  - `inference_patches`：id、runId、nodeId、before、after、appliedAt。
- 撤销：把 run 对应的 patch 按 before 回滚；只允许撤销最近一次，或按 run 列表撤销。
- 失败节点不生成 patch，保持空白。

## 11. 消耗统计

`ai_usage`：

- id、runId、canvasId、kind、provider、model、inputTokens、outputTokens、cachedInputTokens、costUsd、createdAt。

展示：

- 本次：最近一次 run 的 tokens + 费用。
- 本画布合计：按 canvasId 聚合。
- 灵感库操作没有 canvasId，计入全局。

费用：

- 单价表按 provider/model 配置（每 1M tokens）。
- 先按 USD 计算，UI 可加 CNY 近似显示。

## 12. 失败、并发与限流

- 每个画布同时只允许一个推理 run。
- `AbortController` 支持取消。
- 429 / 5xx：指数退避重试 2 次。
- 单节点失败：记录错误，不影响其他节点。
- 无 key：提示去设置页。
- 上下文超限：截断低权重邻居；仍超限则跳过该节点并提示。

## 13. UI

- 顶部「开始推理」：运行中显示进度（3/7）。
- 可选「推理提示」输入框：一句话目标，例如「帮我找出远程办公对创新的约束」。
- 完成后显示「本次 X tokens · $Y」和「撤销」。
- 失败节点显示小红色标记，可重试单个节点。
- 画布顶部显示「本画布合计」。

## 14. 实施阶段

1. **E1 引擎骨架**：任务类型、图快照、波次、上下文、mock adapter、run/patch 表、API、应用/撤销。
2. **E2 Provider**：OpenAI / Claude / DeepSeek 适配、结构化输出、校验/重试、usage。
3. **E3 计费**：单价表、ai_usage、本次/画布合计 UI。
4. **E4 M5b**：候选问题、结果生成、Markdown 文档复用同一任务框架。
5. **E5 优化**：批量调用、缓存、流式结果、评测集。

## 15. 待确认

2. 应用方式：立即应用 + 撤销（推荐）还是先预览再确认？
3. 是否加一个可选的「本次推理提示」输入？
4. 模型：用 provider 默认模型，还是让用户从模型列表里选？
5. 费用显示：USD、CNY，还是只显示 tokens？
