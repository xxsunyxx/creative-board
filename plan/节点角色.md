# 节点角色（讨论稿）

> 2026-10-23 用户提出：也许不需要三种便签，只需要一种，角色由它在图里的位置决定。

## 核心洞察

类型不是便签的属性，而是它在推理链里的位置：

```
[灵感] ──→ [过程] ──→ [结果]
  ↑           ↑           ↑
无入线       有入有出     有入无出
```

- **灵感**：没有入线，有出线（或孤立但被标为灵感）。
- **过程**：有入线，也有出线；连接两端，通常是因果 / 机制 / 转化。
- **结果**：有入线，没有出线；一次汇合 / 收敛。
- **空**：没有入线，也没有出线；等待 AI 或用户补全。

## 空便签补全

用户可以在不知道缺什么的时候插入一个空便签，然后：

1. **作为前驱**：连到已有节点 → AI 推断「需要什么灵感才能推到它」。
2. **夹在中间**：连接两端 → AI 推断「中间过程 / 因果机制」。
3. **作为汇合点**：多个节点连进来 → AI 生成「结果 / 综合」。
4. **完全孤立**：AI 给 3 个候选（灵感 / 过程 / 结果），或让用户先选角色。

## 碰撞

- 两个灵感碰撞 → 生成一个结果节点。
- 显式操作：选中两个节点 → 点「碰撞」。
- 隐式操作：把两个节点连到同一个空节点 → 空节点自动成为结果。
- 结果节点可以继续作为下一轮的输入；这时它的角色是「结果」还是「过程 / 灵感」需要再定。

## 已确认（2026-10-23）

- **过程节点与维度框共存**：过程是便签节点，线上维度框继续保留。
- **角色**：AI 根据入线 / 出线推断，用户可以手动覆盖 / 锁定。
- **碰撞**：先插入一个空结果，再触发推理。
- **推理触发**：不是插入或连线时自动触发；用户把便签布局、连线摆好后，点「开始推理」再生成。
- **插入过程**：把 A→B 拆成 A→P→B；原来的维度框移到 A→P。
- **推理范围**：一次推理画布上所有空便签；每个给一个候选。
- **结果继续连接**：可以继续往外连，角色保持「结果」，不自动变成过程。
- **角色推断 + 手动覆盖**：拓扑给默认角色，用户可以在便签上改。

## 空便签流程

1. 插入空便签，或直接插入「空灵感 / 空过程 / 空结果」。
2. 连线、摆放、调整布局。
3. 点画布的「开始推理」。
4. AI 给每个空便签生成一个候选内容，并推断角色。
5. 用户可以编辑、重生成，或手动改角色。

> 关键：AI 不抢跑。先让用户把结构摆好，再推理。

## Lucky 按钮

- **关系选择器**：随机关系类型 + 随机主 / 细节条件，直接生成维度框。
- **维度面板**：在当前维度树里随机选一个条件。
- 用途：不知所措时给一个可修改的起点，不是最终答案。
- 已实现，两个入口都有 `🎲 Lucky`。

## M5 实现计划

1. 数据模型：`canvas_nodes.type` 改为角色枚举 `inspiration / process / result / blank`，新增 `roleLocked`。
2. 统一便签：角色徽章 / 下拉、角色颜色、空白便签占位、双击编辑正文。
3. 插入菜单：空便签 / 空灵感 / 空过程 / 空结果。
4. 开始推理：扫描画布所有空便签，推断角色、生成一个候选内容。
5. 插入过程：在连接上拆成 A→P→B，原维度框移到 A→P。
6. 结果节点继续连接，角色锁定为结果。
7. 测试：M5a 冒烟 + M1-M4 回归。

## 与维度框的关系

```
[灵感 A] --[维度框]--> [过程 P] --[维度框]--> [灵感 B]
```

- P 是过程节点，前后两段都可以挂维度框。
- 插入 P 时默认拆分 A→B；原维度框全部移到 A→P。
- 空结果节点可以接多个入线，作为汇合点。


现在的「关系类型 + 主维度 + 细节」挂在连接线上。如果过程变成便签节点，有三种做法：

### A. 过程节点取代维度框

```
[灵感 A] ──→ [过程：因果 / 机制 / 沟通成本] ──→ [灵感 B]
```

- 关系类型和维度内容放进过程节点。
- 边变成简单连线。
- 优点：过程可拖动、可缩放、可继续连接；解决 chip 和节点重叠。
- 缺点：一条线上多个关系需要多个过程节点，图会更长。

### B. 两者共存

- 过程节点 + 线上维度框都保留。
- 表达力最强，但最重，容易变成蜘蛛网。

### C. 维度框只保留关系类型

- 线上只显示「因果 / 条件」等标签。
- 主维度和细节维度进入过程节点。
- 折中方案。

## 推荐

- **一个便签原语 + 角色由位置推断 + 可手动覆盖**。
- 过程节点优先于维度框：它更符合「一个便签」的直觉，也能解决当前 chip 重叠的问题。
- 结果节点保留输出面板：候选问题、结果预览、保存文档。
- 角色可以随图变化，但允许用户「锁定角色」，避免 AI 推断错误。
