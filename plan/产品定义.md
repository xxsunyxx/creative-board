# 产品定义（草稿 v0.2）

> 状态：讨论中，不是最终需求；随时可能改。
> 更新：2026-10-23

## 一句话

一个私有的 AI 研究画布：把网页摘录、PDF、笔记、表格和链接摊在画布上，用自然语言让 AI 理结构、生成内容；画布是思考的中间态，最终在独立文档区收敛成结构化笔记。

## 用户

- 首版：自己（验证是否愿意持续使用）。
- 之后：朋友 / 小圈子；支持私有、共创、只读公开。

## 问题

学习 / 研究时，资料散落在浏览器、PDF、笔记和表格里。收集不是最难的，难的是：

- 看完记不住，素材之间没有关系；
- 资料越多，越难判断什么重要；
- 知道要写什么，但整理不出结构；
- 最后产出的笔记和原始资料脱节，无法回溯。

## 产品结构

- **画布**：发散、并置、找关系；允许乱，允许中间态。
- **文档区**：线性、结构化、可回看；承载最终笔记。
- **AI**：在两者之间做整理、生成和搬运；具体交互待定。

## 核心闭环（假设）

1. **收集**：把网页摘录、PDF、笔记、表格、链接放进画布。
2. **摊开**：以卡片 / 分区的方式摆放，建立初步的空间关系。
3. **指令**：选中一张或一组卡片，用自然语言让 AI 归类、命名、补全、生成摘要。
4. **送进文档**：把选中的卡片 / 分组整理成文档结构。
5. **成稿**：在文档区编辑、补写、定稿。
6. **回看**：文档与画布素材保持引用 / 跳转（待定）。

## AI 的角色

- 不是侧边栏聊天机器人，而是画布和文档之间的编辑者。
- 核心动作：**理清结构** + **生成新内容**。
- 交互方式：**待用户描述**。目前已知不是「先提案 / 直接改 / 侧边建议 / 选区自动整理」这几个选项中的任何一个。
- 首版不做：AI 主动打扰、自动改全画布、多人实时协作。

## 首版边界（暂定）

- 私有，单人使用。
- 桌面为主；手机 / 平板后续适配。
- 输入：网页 / 文章摘录、PDF / 论文、自己的笔记、表格 / 数据、链接 / 引用。
- 输出：独立文档区中的结构化笔记 / 摘要。
- 不做：自由绘画、复杂图形设计、音视频解析、公开社区、多人实时编辑。

## 关键风险

1. **画布的必要性**：如果只是「素材 + AI 摘要」，文档工具也能做；画布必须提供空间化思考和关系发现的价值。
2. **画布到文档的过渡**：如果只能手动复制，用户会跳过画布；如果自动生成得太强，用户又失去控制感。
3. **AI 的可控性**：结构修改如果不可预期，用户会不敢用；预览、撤销、局部执行很重要。
4. **资料解析质量**：PDF / 网页的解析和引用溯源决定信任度。
5. **范围膨胀**：三端 + AI + 解析 + 文档，任何一项都能吃掉首版。

## 待确认

- AI 修改的具体交互（等用户描述）。
- 画布到文档的过渡方式。
- 资料导入深度：全文解析，还是先链接 + 摘录？
- 引用 / 溯源的粒度。
- 后台职责与技术选型。
- 手机 / 平板的首个适配端。
