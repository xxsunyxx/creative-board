这两个方向的技术栈、交互方式和首版范围差别很大，先不做假设。

### 候选形态（仅用于讨论，不是提案）

## 2026-10-23 · 第 2 轮：把「实时协作」拆开

### 用户回答（原文）

- 形态：在画板模块里结合灵感墙和 AI 共创画板，产品要和 AI 实时协作工作。
- 用户：朋友 / 小圈子。
- 设备：桌面 + 手机 + 平板。
- 首版目标：自己愿不愿意用。

### 初步解读

这组回答里有几个词需要拆开，否则首版范围会失控：

1. **实时**：是 AI 边聊边生成、改完立刻看到，还是多人同时在线编辑？前者是 AI 交互，后者是协同编辑，技术复杂度差一个量级。
2. **协作**：AI 是工具（我下指令它执行）、助手（它主动提建议），还是画布上的「另一个参与者」（有选区、光标、能直接改动内容）？三种产品感完全不同。
3. **画板**：如果核心是「把散落的灵感变成一条可继续推进的创意方向」，画布只是容器，AI 的整理与联想才是价值；如果核心是「摆得好看」，重点则是素材、布局和导出。
4. **三端**：都覆盖不等于三端同权。更现实的分工可能是手机捕捉、桌面整理、平板手绘/评审，但第一版必须先选一个主创作端。
5. **朋友 / 小圈子**：如果朋友只是看和评论，首版可以不做多人实时编辑；如果要一起改，后台、冲突处理、权限都会变重。

### 本轮要回答的问题

1. 最近一次「要是有这个东西就好了」的具体场景是什么？
2. 一次使用结束时，希望手里留下什么？
3. AI 在画布上最核心的动作是什么？
4. 朋友 / 小圈子第一版主要做什么？

### 用户回答

- 具体场景：学习 / 研究整理。
- 期望产出：一个「相对能收敛的结果」。
- AI 角色：按指令修改——选中元素，用自然语言让 AI 改、重排、延展。
- 朋友参与：可以多人共创，也可以 private，也可以只读 public。

### 解读：重心从「画」转向「想」

「学习 / 研究整理」这个回答很关键。它意味着：

- 画板的主要对象可能不是笔触，而是**资料、笔记、图片、引用和它们之间的关系**；
- 「创意」更接近「把杂乱材料整理出一条主线」，而不是「画出一张图」；
- AI 的核心价值不是生成漂亮素材，而是**理解画布上下文，按指令改动内容与结构**；
- 「相对能收敛的结果」说明用户要的不是无限画布本身，而是从发散到收敛的**过程感**和**终点感**。

这更像一个「AI 原生的研究 / 思考画布」，而不是传统绘画工具。需要确认这个理解。

### 新的关键问题

1. 「收敛」的终点具体是什么形态？笔记、概念图、提纲、结论，还是可讲的展示？
2. 画板上主要放什么资料？网页、PDF、图片、自己的笔记……
3. AI 按指令修改时，最核心的是改文字、理结构、生成内容，还是调布局？
4. 分享的三种模式（私有 / 共创 / 只读公开）首版都要吗？还是先做一种？

### 本轮结论

- 场景锁定为「学习 / 研究整理」，产品更偏「思考画布」而非绘画工具。
- AI 交互锁定为「选中 + 自然语言指令修改」，不是纯聊天。
- 分享希望覆盖私有、共创、只读公开三种模式，但首版优先级待定。
- 三端仍是愿望，首版主创作端待定。

## 2026-10-23 · 第 3 轮：核心闭环

### 用户回答

- 收敛结果：结构化笔记 / 摘要。
- 画板资料：网页 / 文章摘录、自己的笔记、表格 / 数据、链接 / 引用、PDF / 论文。
- AI 重点：理清结构 + 生成新内容。
- 分享：第一版默认私有。

### 解读

1. **产品定位进一步收紧**：不是通用白板，也不是绘画工具，而是「私有 AI 研究画布」。输入是资料，输出是结构化笔记。
2. **分享降级**：首版默认私有，意味着暂时不需要多人实时协作、权限系统、公开链接。后台可以大幅简化，但仍需要账号、存储、资料解析和 AI 代理。
3. **AI 的两个核心动作**：理结构（归类、分组、连线、层级）和生成内容（摘要、提纲、问题、初稿）。这两件事都依赖对画布上下文的理解。
4. **一个需要警惕的张力**：如果最终产出是结构化笔记，用户为什么还需要画布？画布必须提供文档编辑器给不了的东西——空间化聚类、素材并置、关系发现、从发散到收敛的过程感。否则产品会退化成「带 AI 的笔记软件」。
5. **资料类型偏文本**：网页、PDF、笔记、表格、链接，没有图片 / 音视频。这让解析和引用溯源成为关键能力。

### 新的关键问题

1. 画板在流程中负责发散、收敛，还是全程？
2. 结构化笔记放在画板内、独立文档区，还是导出？
3. AI 理结构时，先提案还是直接改？
4. 第一版主设备是桌面、平板还是手机？

### 本轮结论

- 产品收敛为「私有 AI 研究画布」：输入资料，AI 辅助理结构与生成，输出结构化笔记。
- 首版默认私有，多人实时协作和公开分享移出首版。
- 资料类型确定为网页、PDF、笔记、表格、链接，图片 / 音视频暂不优先。
- 已产出 [产品定义草稿](产品定义.md)。

## 2026-10-23 · 第 5 轮：三区结构与特质框

### 用户描述（整理）

1. **三区**：灵感（收集）、画布（头脑风暴）、收敛（结果）。
2. **灵感区**：
   - 支持拖拽、链接、文字收集，形成一条条内容。
   - 两个条目（文档 / 想法）可以拖到一起重新构造：相关 → 融合补充；不相关 → 文字整理。
   - 每条内容生成关键词；关键词可删除、自动生成、手动增加。
3. **画布区**：
   - 灵感发送到画布，成为便利贴。
   - 便利贴周边有连接区；可拖线连接另一个内容；也可两个内容连接到第三个内容。
   - 连接前点击连接区，AI 生成「连接途径 / 特质」；可刷新、回溯。
   - 选定特质后生成链接框（特质框），写入特质；再把特质框连到另一个灵感。
   - 特质框可多层级，例如约束 → 成本 / 资源 / 法规 / 伦理 / 场景 / 能力。
4. **关系词汇**：用户给出一大组方向，包括因果、相关、类比、组合、对立 / 张力、条件、转化、尺度映射，以及机制层级、推理距离、证据强度、时间尺度、作用强度、主体视角、约束、输出用途、可验证性、价值 / 风险等。完整表见 [核心机制](核心机制.md)。
5. **输出框**：连接后出现输出框，内含 AI 生成的候选问题；输出结果放到收敛区。

### 解读

1. **核心差异化出现**：不是「连一条线」，而是「连接前先生成从哪个方向连」。这解决的是「两个东西为什么有关系、通过哪一面发生关系」。
2. **关系被节点化**：特质框是一个可展开、可带属性的中间节点，本质上把边变成了节点。这比普通白板的连线表达力强，但也更复杂。
3. **三区形成完整闭环**：收集 → 连接 → 收敛。画布不再是终点，收敛区才是。
4. **AI 出现在四个位置**：关键词、融合、特质生成、问题与结果生成。每一处的质量都会影响信任。
5. **风险**：特质框概念可能过重；用户可能只想快速连线。需要保留「轻连接」路径。

### 待确认

1. 特质框是 A 的侧面，还是 A 与 B 的关系？
2. 多层级是子特质，还是关系链？
3. 输出框是每条连接一个，还是整组 / 整个画布一个？
4. 灵感融合后原文去留？
5. 三区是同屏三栏，还是切换？
6. 首版 MVP 砍到哪一步？

### 本轮结论

- 产品形态确定为三区：灵感 / 画布 / 收敛。
- 画布的核心机制确定为「连接区 → AI 特质 → 特质框 → 连接」。
- 已产出 [核心机制讨论稿](核心机制.md)，产品定义更新到 v0.3。

## 2026-10-23 · 第 6 轮：修正信息架构

### 用户修正

- 输出框放在画布上，作为流程中的一个显眼依据；生成文档后，会形成一个对应的文档。
- 灵感融合后生成一个新的条目，不是收敛结果；这个条目可以继续作为灵感使用。
- 三区布局不好。灵感是灵感，可以带一个「发送到画布」按钮，发送到指定画布。
- 两个内容连接到的第三个内容，也是普通灵感，或者生成的灵感。

### 解读

1. **信息架构改为「灵感库 + 多画布 + 文档」**：灵感库是独立空间，不跟画布挤在一屏；画布可以有多个；文档是输出框的产物。
2. **融合回到灵感库**：融合不是终点，而是产生一条更成熟的灵感，继续参与后续生成。这形成「灵感 → 融合 → 新灵感 → 上画布 → 输出 → 文档」的循环。
3. **输出框是画布上的流程节点**：不是侧边栏，也不是纯结果页；它标记「这一轮连接已经产生输出」，并对应一篇文档。
4. **第三个节点是灵感，不是特质框**：A + B → C，C 可以是普通灵感或 AI 生成灵感；C 进入灵感库后可以继续用。
5. **布局问题解决**：不再需要三栏；灵感库和画布是两个独立页面 / 空间，通过「发送到画布」连接。

### 待确认

1. 多个画布如何组织？按项目、主题，还是自由创建？
2. 「发送到画布」是复制还是引用？画布上的修改会不会回写灵感库？
3. 输出框是每条连接一个，还是每组连接一个？生成文档后输出框是否保留？
4. 文档放在哪里？独立文档区、画布侧边，还是新页面？
5. 融合后原文是否保留？
6. 特质框统一模型（侧面 + 关系 + 属性）是否确认？

### 本轮结论

- 信息架构改为「灵感库 + 多个画布 + 文档」。
- 灵感融合产物回到灵感库，可继续作为灵感使用。
- 输出框位于画布上，是流程节点，并生成对应文档。
- 两个内容连接的第三个节点是普通灵感或生成的灵感。

## 2026-10-23 · 第 7 轮：侧面框、复制与手动输出

### 用户回答

- 特质框：侧面和关系分开，用两种框。
- 发送到画布：直接复制一份。
- 输出框：手动创建。
- 文档：先有预览结果，保存后写入文档区。

### 解读

1. **关系表达拆成两步**：先选 A 的侧面（哪一面），再选关系（这一面怎么连到 B）。这比一个框塞所有信息更清楚，也更容易复用。
2. **画布和灵感库解耦**：复制意味着画布上的修改不会回写灵感库；灵感库保持稳定，画布可以自由试错。
3. **输出是主动动作**：手动创建输出框，避免每条线都弹输出，画布更干净；但也需要 UI 提示「什么时候该输出」。
4. **预览是必要缓冲**：AI 先生成预览，用户确认后再保存，避免文档区被半成品淹没。
5. **两种框的顺序仍需确认**：目前假设 A → 侧面框 → 关系框 → B。

### 待确认

1. 侧面框和关系框的顺序是否固定？能否只用其中一个？
2. 输出框怎么创建？选中连接后生成，还是先放空框再拖入？
3. 一个输出框能保存几篇文档？
4. 预览能编辑、重新生成、部分采纳吗？
5. 多个画布怎么组织？
6. 融合后原文是否保留？

### 本轮结论

- 采用两种节点：侧面框 + 关系框。
- 灵感发送到画布为直接复制，不同步。
- 输出框手动创建，先预览，确认后保存到文档区。
- 已更新核心机制到 v0.3、产品定义到 v0.5。

## 2026-10-23 · 第 8 轮：多层连接不能砍

### 用户修正

- 连接必须支持多层，不能按 MVP 建议砍成一层。

### 解读

1. **多层不是锦上添花**，而是核心机制的一部分；首版必须保留。
2. **「多层」有四种可能含义**，需要确认：
   - 框内嵌套：约束 → 成本 → 人力成本。
   - 链式连接：A → 侧面 → 关系 → 侧面 → 关系 → B。
   - 跨灵感多跳：A → … → B → … → C。
   - 分层分组：一级关系、二级解释、三级证据。
3. **技术影响**：数据模型从简单边变成树 / 图 / 超图；画布需要折叠、聚焦、分层显示，否则会变成蜘蛛网。
4. **首版可以砍别的**：PDF / 网页解析、移动端、多人、公开、复杂布局都可以后置，但多层连接保留。
5. **最大风险是可读性**：多层连接如果全部平铺，用户会看不懂；需要「展开一层」和「聚焦一条链」的能力。

### 待确认

- 多层具体指哪一种，还是几种组合？
- 多层连接如何展示，避免蜘蛛网？
- 首版保留几层，还是完全不做限制？
- 侧面框 / 关系框的嵌套与链式连接如何区分？

### 本轮结论

- 多层连接是首版必须项。
- 首版切口改为：保留灵感库、画布、侧面框 / 关系框、多层连接、输出框、文档；砍解析、移动端、多人、公开。
- 已更新产品定义与核心机制。

## 2026-10-23 · 第 9 轮：多层连接的三种形态

### 用户选择

- 多层连接包括：框内嵌套、链式连接、跨灵感多跳。
- 不包含分层分组。

### 解读

1. **数据结构是一个带层级节点的有向图**：
   - 灵感节点（起点 / 终点 / 中继）
   - 侧面框（可嵌套）
   - 关系框（可嵌套）
   - 输出框（手动创建）
   - 文档（输出产物）
2. **链式连接**意味着一条连接不是一条边，而是一条路径：A → 侧面 → 关系 → 侧面 → 关系 → B。
3. **跨灵感多跳**意味着路径可以穿过多个灵感：A → … → B → … → C；B 既是上一段的终点，也是下一段的起点。
4. **框内嵌套**意味着侧面 / 关系框本身是树，可以展开子级。
5. **复杂度风险**：三种多层叠加，画布可能迅速变成蜘蛛网；需要折叠、聚焦、分层显示。
6. **输出框的上下文**：多层后，输出框到底以哪条链 / 哪个子图为上下文，需要明确。

### 待确认

1. 链式连接是否允许分支 / 合并？
2. 一条链的起点和终点是否必须是灵感？能否以输出框结束？
3. 框内嵌套是否只做同类嵌套？子级能否向外连接？
4. 首版是否限制层数 / 跳数？
5. 输出框如何选择上下文：整条链、选中的一段，还是整个画布？

### 本轮结论

- 多层连接确认包含：框内嵌套、链式连接、跨灵感多跳。
- 产品数据结构升级为「带层级节点的有向图」。
- 首版必须保留多层，砍其他范围。

## 2026-10-23 · 第 10 轮：图的边界

### 用户选择

- 分支和合并：都允许。

- 嵌套子级：只有最外层框能向外连接。

### 解读

3. **分支 / 合并**意味着灵感节点可以有多个入边和出边；画布必须支持聚焦 / 折叠，否则会乱。

5. 分支 / 合并在画布上怎么显示？

### 本轮结论

## 2026-10-23 · 第 12 轮：连接线 + 维度框，结果与输出分开

### 用户描述（整理）

1. 点击灵感 A，连接到灵感 B。
2. 连接后，线上出现按钮「约束」。
3. 点击「约束」，弹出约束框，里面是 AI 生成的主维度。
4. 点击主维度，显示细节维度，然后选定。
5. 线上仍有按钮：可以框外增加主维度框，也可以框内增加细节维度。
6. 结果和输出要分开；要有灵感，也要有输出。

### 解读

1. **连接线成为主对象**：先连 A-B，再在线上加维度框，而不是先选侧面 / 关系再连线。
2. **维度框是线上的注释 / 面板**，可能不是图节点；一条线可以有多个主维度框，每个框内部有细节维度。
3. **「约束」可能是一个关系类别**，主维度 / 细节维度是这一类别下的层次；需要和之前的侧面 / 关系对齐。
4. **多层的含义进一步明确**：同一条线上可以有多个主维度框，框内可以继续加细节，链可以跨灵感。
5. **结果 vs 输出**：画布上可能同时有灵感节点和输出节点；结果可能是输出节点里的内容，文档是保存后的成稿。

### 待确认

1. 维度框是线上的注释，还是可连接的节点？
2. 「约束」是关系类型吗？主 / 细节维度和侧面 / 关系怎么对应？
3. 结果、输出、文档三者是什么关系？
4. 输出节点能否继续连接？
5. 一条线多个主维度框如何排列？

### 本轮结论

- 连接线优先：先连线，再在线上加维度框。
- 结果 / 输出分开，画布需要同时有灵感和输出。
- 需要重新对齐之前「侧面框 + 关系框」的模型。

## 2026-10-23 · 第 30 轮：便签、全屏与流动连接点

### 用户反馈

- 画布没有默认全屏，虽然做了全屏按钮。
- 便签不够像便签，只是个框。
- 没有「流动的连接点」。
- 便签纸质感太浮夸，希望简洁；图标位置要好；尺寸可调。

### 最终理解

「流动的连接点」不是线上的粒子，而是：

- 连接点根据两个便签中心的向量，自动落在朝向对方的边线上；
- 交换 A / B 的位置后，A 的右侧连接会自动变成 A 的左侧连接；
- 拖动 / 缩放便签时，端点会沿着边缘滑动，像向量一样有指向。

### 实现

- 画布详情页**默认全屏**，侧栏隐藏；可退出全屏恢复侧栏。
- 便签改成简洁纸片：纯色淡底、细边框、顶部色条、圆角、轻阴影；去掉胶带、折角、旋转和重渐变。
- 图标重排：颜色点、标题、权重、删除在顶部；备注在底部；删除 / 备注用 SVG 图标。
- 便签可缩放：右下角手柄，范围 180-520 × 120-480，尺寸落库。
- 连接端点：用 `useInternalNode` 拿节点实时位置和尺寸，计算中心向量与矩形边界的交点；拖拽 / 换位时自动换边。
- 端点圆点 + 四边浮动把手 + 连线流动虚线 / 粒子。
- 四个固定把手保留用于创建连接；已有连接的实际端点由向量计算。

### 验收

- 画布默认 `is-focus = true`。
- 便签从 280×200 拖拽缩放到 340×240，DB 宽高同步。
- 连接端点数量 4（2 条边 × 2 端），拖拽 / 自动排布后跟随节点。
- M3 / M4 测试通过，控制台无报错。

## 2026-10-23 · 第 31 轮：一种便签，三种角色

### 用户想法

- 需要三种便利贴：灵感、过程、结果。
- 可以在不知道缺什么的时候插入空灵感，让 AI 推出需要的灵感。
- 两个灵感碰撞后必然有结果；也许需要一个连接两端的过程。
- 也许只需要一种便签：位置决定角色。
  - 上一个的灵感 → 用结果推灵感。
  - 连接两端 → 由因果推中间过程。
  - 末尾汇集 → 生成结果。

### 解读

核心洞察：**类型不是便签的属性，而是它在推理链里的位置。**

- 无入线、有出线 → 灵感。
- 有入线、有出线 → 过程。
- 有入线、无出线 → 结果。
- 孤立 → 空，等待补全。

这比三种硬类型更简洁，也更适合 AI：AI 可以看邻居、看方向、看缺口，推断「这里该补什么」。

### 关键分叉

过程节点和现有「线上维度框」的关系：

1. 过程节点取代维度框：A → 过程 → B，关系类型和维度进入过程节点。
2. 两者共存：过程节点 + 线上维度框。
3. 维度框只保留关系类型，主 / 细节维度进入过程节点。

推荐先评估第 1 种：它能解决 chip 和节点重叠，也让过程可拖动、可复用、可继续连接。

### 待确认

- 过程节点是否取代维度框？
- 角色自动推断还是手动选？是否允许锁定？
- 碰撞是显式按钮，还是连到同一个空节点自动触发？
- 空便签给一个候选，还是给 3 个？
- 结果继续连接后角色怎么变？

## 2026-10-23 · 第 32 轮：节点角色与推理触发

### 用户选择

- 过程节点与维度框**共存**。
- 角色：AI 推断 + 可手动覆盖。
- 碰撞：**先插入空结果**，再推理。
- 推理触发：完成便签布局后，点「开始推理」，不是自动触发。

### 解读

1. **过程是节点，关系仍可挂在线上**：  
   `[A] --[维度框]--> [过程 P] --[维度框]--> [B]`
2. **AI 不抢跑**：先让用户摆好结构，再显式触发推理。这比自动生成更可控，也更适合「边摆边想」。
3. **空结果先占位**：用户先放一个空结果，接好入线，再让 AI 填内容；这符合「先结构、后内容」。
4. **角色是推断 + 可覆盖**：拓扑决定默认角色，用户保留最终解释权。

## 2026-10-23 · 第 35 轮：推理引擎设计

### 用户问

- 继续，推理引擎怎么设计？

### 设计结论

- 引擎拆成七层：图快照 → 角色推断 → 拓扑波次 → 上下文组装 → provider → 结构化补丁 → 应用/撤销与计费。
- 不做「一次把所有空便签塞给模型」：先按入线拓扑排序，按波次生成；下游节点能看到上游刚生成的内容。
- 每个节点只带 1 跳邻居 + 已选维度路径，按 weight 截断，控制上下文。
- 角色用不同提示词：灵感补前提/素材，过程补机制/因果链，结果收敛结论 + 支撑理由。
- 返回 JSON 补丁，校验 nodeId / role / content；失败节点保持空白。
- 立即应用 + 记录 run / patch，可撤销；`ai_usage` 记录本次和画布合计。
- 后续 M5b 的候选问题、结果生成也复用同一套任务框架。
