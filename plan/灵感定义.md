# 灵感定义（细化稿）

> 灵感不是“随便想一个点子”，而是画布上的一个认识对象。  
> 它有两种认识状态：**已知对象**和**未知对象**。

## 1. 已知对象

标题或提示指向一个现实存在的概念、案例、现象、方法、人、组织或作品。

AI 要做的第一件事：**直接告诉我它是什么**。

内容结构：

1. **定义**：一句话说清它是什么，并划出边界。
2. **关键特质**：它通常具备哪些可观察的特征。
3. **运作方式**：它如何发生 / 如何起作用。
4. **适用条件**：在什么场景、什么前提下成立。
5. **与当前画布的关系**：它为什么出现在这里，会推进哪个下游节点。

约束：

- 不编造来源、数据、人物。
- 不确定时写「我理解它通常指……」，不要把推断写成公认事实。
- 标题保留它原本的名字；不要为了“新颖”改掉已有概念的名称。

示例：

> 团队创新不是“大家多聊天”，而是团队在心理安全的前提下，把不同人的隐性知识拿出来碰撞、试错并重新组合的过程。它通常需要三个条件：足够安全的表达环境、跨角色的高频互动，以及把失败经验留下来的机制。缺一个，互动就可能变成形式上的热闹。

## 2. 未知对象

你无法确认它是否已经存在；或者当前材料里明显缺一个还不存在的东西：一个机制、角色、工具、空间、规则、仪式。

AI 要做的不是硬编事实，而是把它作为一个**工作假设**构造出来：

1. **命名**：先给它一个工作名。
2. **定义**：它是什么类别，不是什么。
3. **可观察特质**：3-4 个，不要只堆形容词。
4. **流程**：什么触发它 → 中间发生什么变化 → 产出什么。
5. **边界**：什么条件下成立，什么时候失效，代价是什么。
6. **关系**：它如何影响当前画布里的下游节点。
7. **不确定性**：明确标注「暂命名 / 待验证」。

命名规则：

- 2-8 个字，尽量是具体的名词短语。
- 能自然地说出「这是一个____」。
- 避免「赋能」「闭环」「生态」「体系」这类没有定义的空词。
- 如果非用不可，先在正文里解释它具体指什么。
- 标题写工作名；可以带一个括号别名。

示例：

> 我暂时把它叫作「弱连接维护机制」。它更像一种组织惯例，而不是工具：在远程办公里，专门为低成本的偶发交流留出固定窗口，让不同小组的人在没有明确议题时也能碰面；触发点是跨组项目开始前，中间变化是信息从强关系圈流向弱关系圈，产出是新的组合机会。它只在心理安全足够、且窗口不被绩效议程占满时成立；如果只是多开一个会，就不是它。暂命名，待验证。

## 3. 判断规则

| 情况 | 判断 | 写法 |
| --- | --- | --- |
| 标题是具体名词、已有概念 | 已知对象 | 直接定义 + 特质 + 适用条件 |
| 用户问「这是什么 / 有哪些」 | 已知对象 | 先回答是什么，再展开 |
| 标题是「空灵感」 | 未知对象候选 | 命名 + 特质 + 流程 + 边界 |
| 上下文缺一个机制 / 角色 / 工具 / 空间 / 规则 | 未知对象 | 构造工作假设，标注待验证 |
| 你不确定它是否存在 | 保守处理 | 用「暂命名 / 我目前无法确认」说明 |

## 4. 与推理引擎的关系

- **标题**：未知对象用工作名；已知对象保留原名。只有空标题或默认标题（空灵感 / 空便签 / 过程 / 空结果）才允许被 AI 标题覆盖。
- **长度**：已知灵感 150-350 字；未知灵感 250-500 字。
- **结构**：1-3 段自然中文，不要小标题、项目符号。
- **下游**：未知对象必须说明它如何影响出线节点，避免成为孤立的概念。
- **校验**：如果正文出现「维度 / 入线 / 出线」等系统词，或原样复制维度短语，重写一次。
- **不自动入灵感库**：生成只是画布上的候选；用户点「存入灵感库」才写入。

## 5. 还没定的

- 是否在界面上显式显示「已知 / 未知」标签？
- 未知对象是否需要一个单独的「命名」字段，而不是复用标题？
- 已知对象是否需要来源 / 引用字段？
- 是否允许 AI 生成多个命名候选？
