只记录已经确认的结论。格式：编号 / 日期 / 结论 / 理由 / 可推翻条件。

## D-001 讨论期不写实现代码

- 日期：2026-10-23
- 结论：在核心形态、目标用户、首版范围达成一致前，不开始编码。
- 理由：形态未定，过早实现会锁死方向，也会把讨论变成「给现有代码找理由」。
- 可推翻条件：用户明确说「开始做」。

## D-002 讨论文档统一放在 `plan/`

- 日期：2026-10-23
- 结论：需求、讨论、决策都记录在 `plan/` 下，不散落在聊天或代码注释里。
- 理由：讨论周期可能较长，需要可回溯的上下文。
- 可推翻条件：无。

## D-003 使用 Git 管理，当前目录为独立仓库

- 日期：2026-10-23
- 结论：在 `creative-board` 内初始化独立 Git 仓库，默认分支为 `main`；远程仓库为 `https://github.com/xxsunyxx/creative-board.git`，当前为 public，`main` 已跟踪 `origin/main`。
- 理由：项目需要独立演进，讨论文档也需要版本历史。
- 可推翻条件：用户决定改为跟随上层仓库，或并入其他仓库。

## D-004 一种便签，四种角色

- 日期：2026-10-23
- 结论：画布只保留一种便签，角色分为灵感 / 过程 / 结果 / 空白；角色由拓扑推断，可手动覆盖。过程节点与线上维度框共存。
- 理由：减少插入时的类型选择，让 AI 根据位置补全；过程节点可拖动、可继续连接，比纯线上注释更灵活。
- 可推翻条件：实际使用中发现角色推断经常出错，或过程节点让图过重。

## D-005 AI Key 只存本机 localStorage

- 日期：2026-10-23
- 结论：OpenAI / Claude / DeepSeek 的 API key 只保存在浏览器 localStorage；测试时由本地服务端临时转发，不写入数据库、不落盘。
- 理由：用户明确要求不在网站中保存 key；本地单用户场景下以简单为先。
- 可推翻条件：需要多设备同步，或安全要求提高到必须使用服务端密钥管理。

## D-006 推理引擎按节点、按波次、可撤销

- 日期：2026-10-23
- 结论：
  - 一次「开始推理」逐节点调用，按入线拓扑波次生成。
  - 结果立即应用，记录 run / patch，可整体撤销。
  - 顶部提供可选的「本次提示」。
  - 模型在设置页测试连接后从 provider 列表里选。
  - 只统计 tokens，不估算费用。
- 理由：逐节点上下文更干净、单节点失败不影响整批；立即应用保持「摆完就推理」的节奏；模型列表避免硬编码过时模型名。
- 可推翻条件：节点很多时逐节点费用/耗时过高，或用户更需要先预览再接受。
