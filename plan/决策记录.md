# 决策记录

只记录已经确认的结论。格式：编号 / 日期 / 结论 / 理由 / 可推翻条件。

## D-001 讨论期不写实现代码

- 日期：2026-10-23
- 结论：在核心形态、目标用户、首版范围达成一致前，不开始编码。
- 理由：形态未定，过早实现会锁死方向，也会把讨论变成「给现有代码找理由」。
- 可推翻条件：用户明确说「开始做」。

## D-002 讨论文档统一放在 `plan/`

- 日期：2026-10-23
- 结论：需求、讨论、决策都记录在 `plan/` 下，不散落在聊天或代码注释里。
- 理由：讨论周期可能较长，需要可回溯的上下文。
- 可推翻条件：无。

## D-003 使用 Git 管理，当前目录为独立仓库

- 日期：2026-10-23
- 结论：在 `creative-board` 内初始化独立 Git 仓库，默认分支为 `main`；远程仓库、可见性和推送方式待定。
- 理由：项目需要独立演进，讨论文档也需要版本历史。
- 可推翻条件：用户决定改为跟随上层仓库，或并入其他仓库。
