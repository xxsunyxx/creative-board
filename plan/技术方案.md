# 技术方案（草案 v0.1）

> 基于：本地优先、单用户、桌面 Web、TypeScript 全栈、AI provider 可切换、Markdown 文档。
> 这是方案讨论，不是实现代码。

## 0. 已确认

- AI：首版先用 **mock provider**，UI / 流程跑通后再接真实模型。
- AI 消耗：M6 接真实接口时记录 token / 费用，显示「本次」和「本画布合计」。
- 预算：先不设上限，后续按实际调用再调。
- 访问：首版本机 + **局域网**，需要时加简单密码。
- 画布体验：支持全屏 / 专注模式；左侧栏可折叠成图标。
- 当前阶段：**M5a 节点角色与推理已通过**；下一步 M5b 结果输出与文档。
- M4 结果：四边连接点、关系选择器、7-8 主维度的维度树、分支 / 合并、Dagre 自动排布、全屏、侧栏折叠跑通。
- M5a 结果：一种便签 + 四种角色、空便签推理、过程拆分、Lucky、正文编辑、AI 设置页跑通。
- M0 结果：React Flow 12.12.0 通过，继续使用；已知多 chip 密集时重叠，后续做避让。
- M1 结果：Next.js 16.4.2 / React 19.3.1 / Drizzle 0.45.4 / better-sqlite3 13.0.3；SQLite 12 张表 + 种子数据 + Server Action 写入跑通。
- M2 / M3 结果：灵感库关键词 / 融合 / 发送到画布；画布便签位置、权重、颜色、备注、删除跑通。

## 1. 结论

- **前端 / 后端**：Next.js（App Router）+ React + TypeScript。
- **画布**：React Flow（`@xyflow/react`）优先，先做技术验证；不行再评估 tldraw / Konva。
- **数据库**：SQLite + Drizzle ORM，本地文件库；后续可换 Postgres。
- **AI**：Vercel AI SDK + provider 适配层，支持 OpenAI / Anthropic / OpenAI-compatible（DeepSeek、通义等）。
- **文档**：Markdown 存储，编辑器 + 预览。
- **部署**：先本地跑；后续再上 Vercel / 云数据库或 Docker。
- **鉴权**：首版本地单用户，不做登录；如果对外暴露，再加简单密码 / Passkey。

## 2. 选型理由

| 层次 | 选择 | 理由 | 备选 |
| --- | --- | --- | --- |
| 全栈框架 | Next.js + React + TS | 一套代码、路由 / API / SSR 都有，适合单人或小团队 | Vite + Node API |
| 画布 | React Flow | 节点、边、缩放、拖拽、选中开箱即用；自定义节点 / 边能力强 | tldraw、Konva、Fabric |
| 样式 | Tailwind CSS + shadcn/ui | 快速搭 UI，组件可控 | Ant Design、MUI |
| 状态 | Zustand + TanStack Query | 画布局部状态 + 服务端数据分离 | Redux、Jotai |
| 数据库 | SQLite + Drizzle | 本地零运维；Drizzle 以后换 Postgres 方便 | Prisma + Postgres |
| AI | Vercel AI SDK | 流式输出、结构化输出、provider 适配成熟 | 各家 SDK 分别接 |
| 文档 | Markdown + 预览 | 简单、可导出、AI 友好 | TipTap 富文本 |
| 测试 | Vitest + Playwright | 单元 + 端到端 | Jest、Cypress |

## 5. AI 流程

7 个调用点：

1. **关键词提取**：灵感内容 → 关键词数组。
2. **灵感融合**：两条灵感 → 新灵感文本 + 关键词。
3. **关系类型推荐**：A / B 内容 + 上下文 → 3-5 个关系类型。
4. **主维度生成**：关系类型 + A / B + 权重 / 颜色 / 备注 → 主维度数组。
5. **细节维度生成**：主维度 + 上下文 → 细节数组。
6. **候选问题**：选中的链 / 组 + 维度路径 → 问题数组。
7. **结果生成**：问题 + 上下文 → 流式 Markdown。

### 上下文组装

- 输入：节点正文、关键词、权重、颜色标签、备注、已有维度路径、相邻节点。
- 优先级：高权重节点优先，低权重节点可截断。
- Token 预算：按模型上下文窗口设置上限，超长时摘要或截断。
- 防抖 / 缓存：相同上下文 + 提示词哈希，命中缓存直接返回。

### 模型路由

- 轻任务（关键词、维度、问题）：便宜 / 快的模型。
- 重任务（融合、结果生成）：更强的模型。
- 配置放在设置页：provider、model、base URL、API key（服务端保存）。

### AI 设置（已实现）

- 支持 OpenAI / Claude / DeepSeek。
- Key 只保存在本机浏览器 `localStorage`，不写入数据库。
- 「测试连接」由 `/api/ai/test` 临时转发到 provider 的 `/models`，用完即弃。
- 测试通过后才能保存到本机。
- M6 真实生成时，客户端把 key 随请求临时传给服务端，不落盘。

### 消耗统计（M6）

- 每次 AI 调用记录：provider、model、input tokens、output tokens、cached tokens、费用。
- 模型单价放在 settings，按 1M tokens 计价；费用 = 输入 / 输出分别计算后相加。
- 画布顶部显示：
  - **本次**：最近一次调用的 tokens 和费用；
  - **本画布合计**：当前画布所有 AI 调用累计。
- 灵感库操作（关键词、融合）没有 canvas 归属，记 `canvas_id = null`，可在设置页看总计。
- 流式结果在结束时写入 usage；结构化输出直接从 provider 响应取 usage。
- mock 阶段不做假计费，显示 0 或「mock」。

## 6. 画布实现

### 节点

- `InspirationNode`：标题、正文、权重输入、颜色控件、备注图标、删除图标、连接点。
- `OutputNode`：候选问题、结果预览（可编辑）、保存按钮、文档数、连接点。
- 节点位置 / 尺寸持久化。

### 边与维度框

- 自定义边 `DimensionEdge`：绘制连线 + 沿线平铺的维度 chip。
- 点击 chip 打开 popover：主维度 / 细节树、手动编辑、刷新 / 回溯。
- 多个维度框沿边分布；密集时收缩 / 折叠。
- 边选中、节点选中、popover 点击之间要处理事件冲突。

> 这是技术风险最高的部分，建议先做 1-2 天的技术验证（spike），只验证：
> 1. 自定义边上放多个可点击 chip；
> 2. chip 打开嵌套 popover；
> 3. 节点拖拽 / 缩放时 chip 跟随；
> 4. 多个 chip 的避让。
> 如果 React Flow 不顺手，再评估 tldraw / Konva。

### 状态与保存

- 画布交互状态用 Zustand。
- 节点 / 边 / 维度的变更防抖保存到服务端。
- 撤销 / 重做：首版可先只做「单步撤销」或后置。
- 乐观更新 + 错误回滚。

## 7. 文档

- Markdown 存储；编辑器 + 预览。
- 首版可以用简单的 textarea / CodeMirror + `react-markdown` 预览。
- 文档与输出节点关联；从文档可以跳回画布。
- 导出 Markdown 文件后置。

## 8. 本地运行

- `pnpm dev` 启动 Next.js。
- SQLite 文件放在 `data/app.db`。
- 环境变量：AI provider / API key / 模型名。
- 首版本地单用户，不做登录；如果要在局域网访问，加简单密码。

## 10. 风险

1. **自定义边上的交互**：React Flow 能否顺畅承载多个 chip + popover，需要 spike 验证。
2. **AI 成本 / 延迟**：多层上下文容易变长；需要缓存、截断、模型路由。
3. **画布可读性**：多个维度框 + 多跳 + 分支，容易变蜘蛛网；需要折叠 / 聚焦。
4. **备注追加膨胀**：备注每次追加，灵感文字会变长；需要折叠 / 分页。
5. **自动保存冲突**：拖拽 / 编辑 / AI 同时改数据，需要版本号或最后写入策略。
6. **范围膨胀**：首版必须严格按 MVP 清单，不提前做 PDF / 多人 / 移动端。
