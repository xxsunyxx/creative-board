# E1 推理引擎骨架

> 目标：把「开始推理」从 mock server action 换成正式的图推理流水线。

## 已完成

### 数据

- `inference_runs`：一次推理的 run、状态、provider、model、hint、错误、开始/结束时间。
- `inference_patches`：每个节点的 before / after、应用时间、撤销时间。
- `ai_usage`：每次 provider 调用的 input / output / total tokens。
- 迁移 `0002_gigantic_storm.sql`；`pnpm db:check` 可在空库跑通。

### 引擎

- `snapshot.ts`：加载画布节点、边、维度框、已选维度路径。
- `planner.ts`：找空便签、按入线做拓扑波次。
- `context.ts`：每个节点只带 1 跳邻居 + 已选维度路径，按 weight 排序、截断正文。
- `prompts.ts`：灵感 / 过程 / 结果三套提示词 + JSON 输出要求。
- `adapters.ts`：mock、OpenAI、Claude、DeepSeek；JSON 解析、usage 归一化、错误脱敏。
- `run.ts`：逐波次逐节点调用、生成补丁、应用 DB、记录 run / patch / usage；整体撤销。

### API

- `POST /api/ai/infer`：`{ canvasId, hint, provider, model, apiKey }` → patches / usage / canvasTokens。
- `POST /api/ai/infer/undo`：`{ runId }` → 按 before 回滚。
- Key 只在请求体里，不写日志、不落盘。

### UI

- 顶部「本次提示（可选）」输入。
- 开始推理后显示「已推理 N 个 · X tokens」。
- 显示「本次 X tok · 画布 Y tok」。
- 推理成功后出现「撤销」；刷新页面后仍可撤销最近一次未撤销的推理。
- 无 AI 配置时用 mock，便于本地验证。

### 设置

- 测试连接后拉取 provider 的 `/models`。
- 过滤非 chat 模型（embedding / tts / image / audio / realtime 等）。
- 用户选模型，和 provider / key 一起存 localStorage。
- 测试通过且选了模型才能保存。

## 验收结果（2026-10-23）

- `pnpm check:engine`：
  - 2 个空灵感 + 1 个空结果，2 条入线。
  - 推理后 3 个节点都有内容。
  - `inference_runs` 1 条 succeeded。
  - `inference_patches` 3 条。
  - `ai_usage` 3 条，mock 0 tokens。
  - 撤销后 3 个节点正文清空，patch 写入 `undone_at`。
  - 刷新页面后「撤销」仍可见，点击后同样回滚。
- `pnpm check:m5` 继续通过：插入、连接、推理、过程拆分、角色、Lucky、正文编辑。
- `pnpm check:settings` 通过：key + model 读写、清除。
- `pnpm typecheck` / `pnpm build` / `pnpm db:check` 通过。

## 已知限制

- 真实 provider 只用代码和错误处理验证过，尚未用真实 key 跑通（没有 key）。
- 逐节点串行调用；没有并发 / 进度条 / 流式。
- 没有单节点重试按钮；失败节点只在状态里提示。
- mock 的 usage 为 0，token 展示要等真实调用才有数字。
- 结果节点的问题 / 文档面板还没做（M5b）。
